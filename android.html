Android 导入页

先按客户端选择入口。Android 端主要是域名、关键词、IP、DNS 和 routing 规则，不包含 iOS 的 Script / MITM / Rewrite 能力。

不确定怎么选：已有节点用 Mihomo 规则集版；没有节点才用完整配置版；只想增强某个 App，就进 App 可选增强规则。

先选入口

已有节点选 Mihomo 规则集版，不会覆盖原节点和策略组。
没有节点选 完整配置版，作为完整 Clash / Mihomo 配置导入。
单 App选 App 可选增强规则，只添加需要的 App 文件。
AdGuard选 DNS 规则版，只能做域名级拦截。
sing-box选 sing-box rule-set，需要在自己的配置中引用。
v2rayNG选 routing 片段版，需要手动合并。

安卓 Clash Meta / Clash Mi 使用注意：
  • 使用 Clash Meta / Clash Mi 导入安卓配置后，需要关闭「分应用代理」。
  • 如果开启「分应用代理」，部分 App 可能不会经过代理规则。
  • 可能导致模块不生效、去广告无效、YouTube / Bilibili / 今日头条等模块异常、规则没有命中。
  • 建议关闭分应用代理，让 Clash 接管全部应用流量。
  • 修改后请重启 Clash Meta / Clash Mi，并重新打开需要测试的 App。

App 增强规则

App 可选增强规则

用于手动加强 YouTube、Spotify、国内常见 App 等覆盖。按需添加，不建议一次性全开。

可选单 App组合包
▰ 规则索引Apps
不要同时启用 Domestic-Apps 组合包和大量单 App 文件。异常时先关闭对应 App 增强规则。

iOS 可复用规则包

从 iOS reject 规则提取 Android 可识别规则，覆盖更强，也更容易误伤。

增强包更强覆盖更易误伤

合并示例

已有节点用户 Mihomo rule-provider 示例 
rule-providers:
  grandpaniu_ads:
    type: http
    behavior: classical
    format: yaml
    url: "https://raw.githubusercontent.com/GrandpaNiuu/GrandpaNiu/main/Android/mihomo/GrandpaNiu-Ads.yaml"
    path: ./ruleset/GrandpaNiu-Ads.yaml
    interval: 86400

rules:
  - RULE-SET,grandpaniu_ads,REJECT
  - MATCH,🚀 节点选择
规则必须放在 MATCH、GEOIP、普通代理分流规则之前。iOS 可复用规则包如果额外加入，也要放在 MATCH 之前。

边界说明

Android 版只迁移域名、关键词、IP 规则和部分可迁移拦截逻辑，不包含 iOS / Surge / Shadowrocket 的 Script、MITM、Rewrite、Header Rewrite、Body Rewrite 能力。

risky/ 目录只用于排查。它可能影响 App 启动、图片加载、播放、定位或接口连接，不建议长期启用。
一键导入失败时，请复制对应链接，在客户端中选择「从 URL 导入」或按教程手动合并。
