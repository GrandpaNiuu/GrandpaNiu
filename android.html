GrandpaNiu · Android Rules

Android 单一入口

所有 Android 规则层已经合并到各客户端主输出里。普通用户优先使用 Mihomo 主规则集；sing-box、AdGuard、v2rayNG 作为同源同步规则分支保留，并跟随 Mihomo 同步构建。

不要再单独叠加 iOS 兼容层、单 App 包或零散增强包。主输出已经合并这些安全可迁移规则，重复导入只会增加误伤和排查难度。

唯一推荐入口

GrandpaNiu Android 主规则集

适合 Mihomo、Clash Meta、FlClash 等支持 rule-provider 的客户端。这个入口已经合并 Android 原生规则、iOS 通用兼容层和 iOS App 兼容增强层，不需要再导入其他增强包。

推荐 单一入口 已聚合 iOS 兼容层 不会覆盖节点
https://grandpaniuu.github.io/GrandpaNiu/Android/mihomo/GrandpaNiu-Ads.yaml
这是 Android 的唯一推荐入口。sing-box、AdGuard、v2rayNG 是同一套合并规则的同步分支，不是需要重复叠加的增强包。

接入方式

Mihomo / Clash Meta / FlClash 配置片段 
rule-providers:
  grandpaniu_ads:
    type: http
    behavior: classical
    format: yaml
    url: "https://grandpaniuu.github.io/GrandpaNiu/Android/mihomo/GrandpaNiu-Ads.yaml"
    path: ./ruleset/GrandpaNiu-Ads.yaml
    interval: 86400

rules:
  - RULE-SET,grandpaniu_ads,REJECT
  - MATCH,节点选择
规则必须放在 MATCH、GEOIP 和普通代理分流规则之前。主规则集已经是合并输出，不需要再额外导入单 App 包或 iOS 兼容层。
安卓 Clash Meta / Clash Mi 使用注意：
  • 使用 Clash Meta / Clash Mi 导入安卓配置后，需要关闭「分应用代理」
  • 如果开启「分应用代理」，部分 App 可能不会经过代理规则
  • 可能导致模块不生效、去广告无效、YouTube / Bilibili / 今日头条等模块异常、规则没有命中
  • 建议关闭分应用代理，让 Clash 接管全部应用流量
  • 修改后请重启 Clash Meta / Clash Mi，并重新打开需要测试的 App

同步规则分支

sing-box / AdGuard / v2rayNG 同步分支
下面三个文件和 Mihomo 主入口来自同一套规则源，并由同一次构建生成。只在对应客户端里使用一个，不要跨格式重复启用。

sing-box

合并后的 rule-set JSON，需要手动放入自己的 sing-box 配置。

AdGuard

合并后的 DNS 过滤文本，只能做域名级拦截。

v2rayNG

合并后的 routing 片段，不是完整节点订阅，需要手动合并。

这里保留的是同步规则分支，不是额外增强层。遇到图片不加载、登录异常、白屏、播放异常时，只保留当前客户端对应的一个合并版排查。

边界说明

Android 版只迁移域名、关键词、IP、DNS 和 routing 规则，不包含 iOS / Surge / Shadowrocket 的 Script、MITM、URL Rewrite、Header Rewrite、Body Rewrite 能力。登录、支付、银行、验证码、视频播放、图片 CDN 保护链路不会被迁移成 Android 拦截规则。

如果你只想“像 iOS 一样一个入口”，就只使用本页的 Mihomo 主规则集。sing-box、AdGuard、v2rayNG 是跟 Mihomo 同步生成的规则分支，用于对应安卓客户端。
导入失败时，请复制主入口链接，在客户端中选择“从 URL 导入规则集”或按配置片段手动合并。
