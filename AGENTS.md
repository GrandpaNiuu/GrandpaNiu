# GrandpaNiu AI Maintenance Rules

GrandpaNiu is a Shadowrocket / Surge / Android / Windows routing and advertising cleanup repository. Treat it as high risk: a small rule, script, MITM, or routing change can break login, payment, media playback, image/CDN loading, or normal app networking.

AI assistants and maintainers must use repository records as the source of truth. Do not rely only on chat history.

## Required Startup Reading

Before starting any work, read:

- `PROJECT_STATE.md`
- `AI_HANDOFF.md`
- `docs/ai/TASKS.md`
- `docs/ai/DECISIONS.md`
- `docs/ai/RISK_LOG.md`
- `docs/ai/SELF_REVIEW.md`
- Recent entries in `docs/ai/WORKLOG.md`

If any required record file is missing or unreadable, create or repair the maintenance record first. Do not touch business logic, routing rules, scripts, workflows, release outputs, or generated files until the maintenance records exist.

## Required Pre-Change Checks

Before every modification, run:

```bash
git status
git branch --show-current
```

If there are uncommitted changes, explain them first. Do not overwrite, delete, normalize, reformat, or silently modify user changes.

## Commit And Push Rules

- Do not automatically commit unless the user explicitly asks for a commit or the active task clearly requires publishing changes.
- Do not automatically push unless the user explicitly asks for remote publishing or has already established that maintenance changes should be pushed.
- Never commit local private logs.
- Keep `../_codex_private_logs/GrandpaNiu/` local-only.
- Suggested commit messages should use `codex: short description of the completed change` unless the user provides a specific message.

## Formatting Rules For AI Records

- AI maintenance Markdown files must remain readable Markdown.
- Do not collapse headings, lists, tables, or command blocks into single-line text.
- Keep commands in fenced code blocks when documenting procedures.
- Keep one command per line inside command blocks.

## Safety Rules

1. Do not perform unrelated refactors.
2. Do not run broad formatting on unrelated files.
3. Do not run dangerous commands without explicit confirmation:
   - `git reset --hard`
   - `git clean -fd`
   - force-overwriting many files
   - deleting core directories
   - deleting `Release/`, `Rules/`, `Rewrite/`, `Scripts/`, `Android/`, `Windows/v2rayN/`, or other key directories
   - changing public module entry points
   - changing repository version strategy
4. Keep the current Fusion single-module public strategy unless the owner explicitly changes it.
5. Do not casually reintroduce Stable, Lite, Full, Aggressive, or other public multi-version routes.
6. Do not casually change public entries:
   - `Ronghemokuai.sgmodule`
   - `Release/Module.sgmodule`
   - `Release/Ronghemokuai.sgmodule`
7. Before changing rules, identify the source layer:
   - `Rules`
   - `Rewrite`
   - `Scripts`
   - `Android`
   - `Windows/v2rayN`
   - `Release`
   - `tools`
   - GitHub Actions workflows
8. Do not directly edit generated outputs unless you have confirmed the file is not generated by the build system.
9. Treat login, payment, banking, captcha, video playback, image/CDN paths, account systems, and normal app networking as protected high-risk traffic. Write a risk note before changing them.
10. Only perform source-first rule changes when there is real app abnormal behavior, client logs, packet captures, or another reproducible signal.
11. Do not add VIP unlock, paid membership unlock, payment bypass, login bypass, receipt forgery, piracy enablement, credential theft, account-sharing bypass, or traffic interception logic.
12. Prefer source-first changes under:
    - `Rules/`
    - `Rewrite/Sources/`
    - `Rewrite/Remotes/`
    - `Scripts/`
    - `Android/`
    - `Windows/v2rayN/`
    - `tools/`
13. Keep changes narrow. Modify only the files directly related to the current task.
14. If a requested change may break protected traffic or public module compatibility, stop and explain the risk before editing.

## Required Finish Checks

After each change, inspect:

```bash
git diff --stat
git diff
```

Run the narrowest relevant checks first.

When touching build, rules, scripts, workflows, or generated release outputs, prefer:

```bash
python Rewrite/Generator/Builder.py --profile fusion --release --check
python scripts/quality_gate.py
python scripts/validate_repository.py
python scripts/repository_health_check.py
```

For documentation-only changes, business builds are not required, but the reason must be stated in the final report.

If a check cannot be run, explain why and record the limitation in the work log.

## Required Self-Review

Before the final response, commit, or push, review `docs/ai/SELF_REVIEW.md`.

For meaningful work, add a `Self-Review` section to `docs/ai/WORKLOG.md` that records:

- what was not good enough
- what was changed to reduce that risk
- what should be checked first next time

## Required Record Updates

Update these records before finishing meaningful work:

- `PROJECT_STATE.md`
- `AI_HANDOFF.md`
- `docs/ai/WORKLOG.md`
- `docs/ai/TASKS.md`
- `docs/ai/SELF_REVIEW.md` when the checklist itself changes

Update these when relevant:

- `docs/ai/DECISIONS.md`
- `docs/ai/RISK_LOG.md`

The work log entry must include:

- Task summary
- Starting branch and git status summary
- Files changed
- Reason for each change
- Commands run
- Test or validation result
- Risks
- Self-review
- Next step

## Local Private Logs

Private working notes live outside the repository at:

```text
../_codex_private_logs/GrandpaNiu/
```

Do not submit that directory to Git. It may contain command notes, debugging details, local paths, longer work logs, and temporary investigation notes.

If `_codex_private_logs` is found inside the repository, do not commit it. Report it to the user and ask whether it should be moved outside the repository.

## Final Response Requirement

At the end of each task, report:

1. What was changed
2. Which files were changed
3. What checks were run
4. Whether the repository has uncommitted changes
5. What risks remain
6. Self-review summary
7. What should be done next
