## 记录规则

- 真实测试通过后再把结果改为“通过”。
- 出现异常时填写异常说明，并保留对应提交号或模块版本。
- 大改后至少复测 Spotify、YouTube、知乎、登录、支付、验证码。
- 涉及 MITM、Body Rewrite、Map Local 或大型 JSON 改动后，必须重新测试高风险 App。

## 测试步骤模板

### 通用前置步骤

1. 在 Shadowrocket 中更新模块、更新脚本、更新全部资源。
2. 确认模块版本日期与 `Ronghemokuai.sgmodule` 顶部 `#!desc` 一致。
3. 开启日志，记录异常 App、触发时间、网络环境、模块版本和最近 commit。
4. 测试前后分别截图保留关键页面，异常时不要直接写“通过”。

### Spotify

1. 打开首页，确认首页加载正常。
2. 搜索任意歌曲或歌手。
3. 连续播放 3 首歌。
4. 手动切歌 5 次。
5. 打开歌单并播放。
6. 记录是否出现无法播放、加载失败、登录异常或广告残留。

### YouTube

1. 打开首页并刷新。
2. 搜索关键词。
3. 播放普通视频 3 分钟。
4. 打开 Shorts。
5. 打开评论区。
6. 记录是否出现黑屏、无法播放、评论加载失败、账号异常或广告残留。

### 知乎

1. 打开首页推荐流。
2. 打开回答详情页。
3. 搜索关键词。
4. 打开评论区。
5. 测试点赞和收藏入口，但不要测试付费内容绕过。
6. 记录是否出现登录异常、页面空白、付费内容异常或广告残留。

### Bilibili

1. 打开首页推荐。
2. 搜索关键词。
3. 播放普通视频。
4. 打开评论区。
5. 记录是否出现播放失败、评论失败、账号异常或广告残留。

### 淘宝 / 京东 / 拼多多

1. 打开首页。
2. 搜索商品。
3. 打开商品详情页。
4. 加入购物车，但不要实际付款。
5. 打开订单页。
6. 记录是否出现登录异常、验证码异常、购物车异常、订单页异常或广告残留。

### 微信 / 支付宝 / 银行 App

1. 测试登录状态是否正常保持。
2. 测试验证码页面是否能正常加载。
3. 只测试支付前置流程，不进行真实大额付款。
4. 测试消息推送和页面跳转。
5. 任一异常都应优先回查 MITM、Body Rewrite、Map Local。

## 判定标准

- “通过”：核心流程无异常，且没有明显误杀。
- “部分通过”：核心流程可用，但有广告残留或局部异常。
- “失败”：登录、播放、支付前置、验证码、订单等核心流程异常。
- “未测试”：没有真实手动操作，不得改成通过。
